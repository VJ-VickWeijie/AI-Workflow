# 生命周期

| 阶段 | 退出成果 | 默认决策点 |
| --- | --- | --- |
| M0 目标探索 | 目标、范围、约束、成功条件 | 是否确认目标进入评审 |
| M1 多角色评审 | 备选方案、反对意见、证据、推荐 | 是否值得继续 |
| M2 专业设计 | 项目专用设计、假设、风险 | 是否采纳方案 |
| M3 实施规划 | 任务依赖、责任人、资源、验收断言 | 是否授权实施 |
| M4 自主执行 | 交付物、自检、运行证据 | 是否接受阶段成果 |
| M5 独立验收 | 原始证据、缺陷与复验、结论 | 是否通过验收 |
| M6 交付复盘 | 成果链接、交接、经验与后续 | 是否结束或启动下一轮 |

项目启动时定义目标、范围、约束、预算、产出、验收标准、升级条件及所需审批点。M3 计划中应列出哪些阶段转换需要项目所有者批准。默认在 M0/M1 目标或价值决策、M2 方案采纳、M3 执行授权、M4/M5 阶段验收、M6 结束或启动新一轮时设置审批。相邻阶段可以合并为一个里程碑，但必须保留各自的成果与审查证据。项目所有者可在授权计划中合并审批点。新增或移除已批准的审批点须先提交变更。

每个工作包记录负责人、输入与依赖、工具、完成条件、验证方式和失败处理。无依赖且写入资源互斥的任务可并行。协调者整合结果，并记录角色与模型分配。

按项目复杂度合并或拆分里程碑，并记录实际审批点。合并 M4/M5 时保留执行与独立审查两类证据。软件可用产品需求与规格，动画可用剧本、分镜及成片，研究可用假设、实验与证据。普通返工在本阶段内处理。
